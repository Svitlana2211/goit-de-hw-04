# Домашнє завдання 4

## Apache Spark — оптимізація та SparkUI

У роботі досліджено вплив додаткового виклику collect() та кешування проміжного результату на кількість завдань у SparkUI.

## Середовище виконання

- Ubuntu через WSL
- Visual Studio Code
- Apache Spark 3.5.5
- Python 3.12.3
- Java 11

## Частини роботи

| Файл | Опис | Завершені завдання |
|---|---|---:|
| part1.py | Один виклик collect() після всіх перетворень | 5 |
| part2.py | Два виклики collect() без кешування | 8 |
| part3.py | Два виклики collect() з кешуванням через cache() | 7 |

## Висновки

Додатковий collect() без кешування запускає окреме виконання плану. У другій частині кількість завдань збільшилася з 5 до 8.

Використання cache() дозволяє повторно використовувати обчислений проміжний результат. У третій частині кількість завдань зменшилася до 7.

Ці результати отримано для наведених програм у Spark 3.5.5.

## Запуск

Файл даних nuek-vuh3.csv потрібно розмістити в одній папці з програмами.

Програми запускалися по черзі з цієї папки:

- ~/spark/bin/spark-submit part1.py
- ~/spark/bin/spark-submit part2.py
- ~/spark/bin/spark-submit part3.py

Під час очікування введення з клавіатури результати переглядалися на сторінці http://localhost:4040/jobs/.
